## Что изменилось

### 1. requirements.txt (новый файл)
Все зависимости одной командой: `pip install -r requirements.txt`.
Ловушка, из-за которой обучение стартовало на CPU: обычный
`pip install torch` на Windows ставит сборку без GPU. Теперь
CUDA-индекс прописан прямо в requirements.txt (`--extra-index-url`)
и диапазон версий ограничен (`torch>=2.2,<2.7`), чтобы pip не утащил
более новую CPU-сборку с PyPI. Проверка после установки:

    python -c "import torch; print(torch.cuda.is_available())"

должно напечатать True.

### 2. Авто-стек: N_STACK читается из весов, а не из константы
Раньше стек кадров был захардкожен в каждом скрипте (4/4/8 — источник
«сплит-брейна» из аудита). Теперь:
- train_stage.py: при --resume стек берётся из указанного .zip;
  старт с нуля — N_STACK=8;
- dagger_train.py: при --base — из .zip базы, при --resume-bc — из .pt;
  from-scratch — 8;
- play.py / diagnose_v2.py / servo_v2.py уже читали стек из модели;
- bc_train.py: N_STACK 4 -> 8 для НОВЫХ прогонов — единая 60Гц-линия
  (у стека-4 на 60Гц всего 67 мс истории против 133 мс у стека-8).
Новый хелпер: models.infer_stack_file(path) — работает и с .zip
(PPO-модель), и с .pt (state_dict BCNet).

### 3. ФИКС: ложная тревога Δlogits-гейта в bc_train (самоаудит)
Гейт в конце bc_train сравнивал нормализованные логиты PPO-распределения
с СЫРЫМИ логитами BCNet. torch Categorical при создании вычитает
logsumexp, поэтому даже при побитово точном переносе гейт показывал
~3.3 и печатал «перенос сломан». Доказано экспериментально:
разница была ровно константой -logsumexp. Исправление: log_softmax
с обеих сторон (+ добавлена проверка кнопочной головы, её не было).
После фикса: max|Δ| = 4.8e-07 на стеках 4 и 8 (было ~3.3).

### 4. GPU-предупреждение при старте bc_train / dagger_train
Если torch не видит GPU — печатаются готовые команды лечения
(те самые две команды из разговора про device: cpu).

### 5. Подсказка про ОЗУ
bc_train теперь печатает размер кольцевого буфера. Со стеком 8 это
~4.6 ГБ ОЗУ (со стеком 4 было ~2.3 ГБ). Если не влезает — скажи,
ужмём BUF_SIZE.
